# Руководство для контрибьюторов

## Структура проекта

Это Maven-модуль Spring Boot для уведомлений. Исходный код находится в `src/main/java/ru/rom8/rescue/notification/`: приложение, Kafka-обработчик, сервисы и модели сообщений. Схема событий Avro расположена в `src/main/avro/NotificationEventV1.avsc`; Maven генерирует классы Avro при сборке. Конфигурация — в `src/main/resources/application*.yml`, текстовые шаблоны уведомлений — в `src/main/resources/messages/{in-progress,success,fail}/`.

Тесты находятся в `src/test/java/` и используют фикстуры ожидаемых сообщений из `src/test/resources/messages/`. Новые пакеты должны следовать базовому пространству имён `ru.rom8.rescue.notification`.

## Сборка, тестирование и запуск

```bash
mvn clean verify                 # очистить, сгенерировать Avro и выполнить все проверки
mvn test                         # запустить модульные тесты
mvn -Dtest=MessageServiceTest test # запустить конкретный тестовый класс
mvn spring-boot:run              # запустить сервис локально
```

Для локального запуска проверьте настройки Kafka и окружение в `application-dev.yml`; не добавляйте секреты в репозиторий. `docker`/Testcontainers может потребоваться для интеграционных тестов, если они будут добавлены.

## Стиль кода и тесты

Используйте Java-стиль проекта: 4 пробела, фигурные скобки, явные типы, `final` для неизменяемых локальных значений и конструкторную инъекцию зависимостей. Имена классов — `PascalCase`, методов и переменных — `camelCase`, констант — `UPPER_SNAKE_CASE`. Kafka-события и Avro-типы должны сохранять версию в имени (`...V1`).

Тесты пишите на JUnit 5 с AssertJ; имена методов описывают поведение, например `createsSuccessMessageWithExpectedTitleAndBody`. При изменении шаблонов обновляйте соответствующие файлы `*_expected.txt`. Для новой логики добавляйте позитивные и граничные сценарии; перед PR тесты должны проходить через `mvn clean verify`.

## Коммиты и Pull Request

История использует короткие повелительные сообщения на русском, например `Добавить формирование сообщений по шаблонам`. Сохраняйте этот стиль и описывайте одну логическую правку на коммит.

PR должен содержать цель изменения, краткое описание реализации, результаты `mvn clean verify` и связанные issue (если есть). Для изменений пользовательского текста приложите пример результата или явно перечислите изменённые шаблоны.
